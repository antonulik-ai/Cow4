## Ответы на вопросы

### 1. Как обеспечена доступность?

Для доступности использованы семантические
теги header, main, section, form и footer.

Для каждого поля добавлен label,
связанный с input через атрибут for.

Все кнопки доступны с клавиатуры.
Для полей предусмотрена подсветка при фокусе.

Для сообщения об авторизации используется
aria-live="polite", чтобы скринридер мог
сообщать пользователю об изменении текста.

Также добавлен адаптивный дизайн,
чтобы формой было удобно пользоваться
на телефонах и компьютерах.

### 2. Почему выбраны Flexbox и Grid?

В проекте используется Flexbox для выравнивания
элементов по горизонтали и вертикали.

Например, он применяется для центрирования
формы и расположения социальных кнопок.

Обычная блочная модель используется
для вертикального расположения элементов.

Я выбрал Flexbox, потому что он простой
в использовании и хорошо подходит
для небольших форм авторизации.

CSS Grid для такой простой формы
не является необходимым.

### 3. Почему выбраны такие брейкпоинты?

Используется брейкпоинт 480 пикселей.

При ширине экрана меньше 480px
карточка занимает всю доступную ширину,
а внутренние отступы уменьшаются.

Это сделано для удобного отображения
формы на небольших смартфонах.

### 4. Почему выбран localStorage?

Для сохранения электронной почты
используется localStorage.

Он позволяет хранить данные в браузере
даже после закрытия страницы.

В проекте сохраняется только почта пользователя.

Пароль не сохраняется, потому что
это может быть небезопасно.

В реальных приложениях авторизация
должна выполняться на сервере.

### 5. Какие функции использовались?

В проекте используются именованные
и стрелочные функции.

Именованная функция применяется
для обработки отправки формы.

Стрелочные функции используются
для коротких обработчиков кнопок.

Мне больше нравятся именованные функции,
потому что их проще читать и понимать.
Однако оба варианта полезны
и зависят от конкретной задачи.
